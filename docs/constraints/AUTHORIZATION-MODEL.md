# 授权分级模型

> **核心原则：不是所有操作 AI 都能自主决定。关键决策必须有人工把关。**

---

## 一、为什么需要授权分级

| 无分级的后果 | 分级后的保护 |
|------------|------------|
| AI 随意修改核心架构 | 架构变更 = 需要人工审批 |
| AI 随意引入新依赖 | 新依赖 = 需要安全审查 |
| AI 随意删除/重写代码 | 破坏性变更 = 需要变更请求 |
| AI 自我验收通过 | 关键 gate = 独立验证 |

---

## 二、操作分级矩阵

| 级别 | 操作类型 | 示例 | AI 权限 | 所需审批 |
|:---:|---------|------|--------|---------|
| **L0** | **只读/查询** | 读取文件、搜索代码、查看日志、运行测试（只读） | ✅ **完全自主** | 无 |
| **L1** | **局部编码** | 实现函数、编写测试、修复 Bug、更新文档 | ✅ **自主执行** | 任务模板验收 |
| **L2** | **模块级变更** | 新建模块、重构模块内部、修改接口签名 | ⚠️ **需任务存在** | TASKS.md 已规划 + 设计文档通过 |
| **L3** | **架构/跨模块** | 修改核心数据流、变更数据库 Schema、调整服务边界 | 🔴 **需人工审批** | ADR + 架构师签名 + CR |
| **L4** | **基础设施/安全** | 修改 CI/CD、引入新依赖、改动部署配置、密钥管理 | 🔴 **禁止 AI 直接操作** | 安全审查 + 运维审批 + CR |
| **L5** | **破坏性/不可逆** | 删除模块、重写核心、强制推送、数据库迁移回滚 | 🔴 **绝对禁止 AI** | 仅限人工执行 |

## 三、详细权限表

### L0 - 只读查询（完全自主）

| 操作 | 说明 |
|------|------|
| `Read` / `Glob` / `Grep` | 任意文件 |
| `Bash` (只读命令) | `cat`, `ls`, `git log`, `git diff`, `go test`, `npm test` |
| `Task` (只读子任务) | 代码搜索、文档调研 |
| `WebFetch` / `WebSearch` | 查阅官方文档、搜索方案 |

---

### L1 - 局部编码（任务内自主）

| 操作 | 前置条件 | 验收 |
|------|---------|------|
| `Write` / `Edit` (src/、tests/) | 任务 T-XXX 在 TASKS.md 中为 🔄 状态 | `verify-task.sh` 通过 |
| 编写单元测试 | 对应实现代码已存在 | 覆盖率达标 |
| 更新模块文档 | 代码已变更 | 文档与代码一致 |
| 修复 Lint 错误 | 非架构层面 | 自动修复优先 |

---

### L2 - 模块级变更（需规划存在）

| 操作 | 前置条件 | 审批流程 |
|------|---------|---------|
| 新建模块目录结构 | ADR-XXX 已接受 + 模块设计文档通过 | TASKS.md 已拆解任务 |
| 修改公共接口签名 | 所有调用方已识别 + 兼容性方案 | 更新 REQUIREMENTS.md + 通知相关任务 |
| 重构模块内部实现 | 不对外暴露接口变更 | 回归测试 100% 通过 |
| 新增内部依赖 | 依赖已在 ADR-002 允许列表 | 无需额外审批 |

---

### L3 - 架构/跨模块（需人工审批）

| 操作 | 触发条件 | 审批流程 |
|------|---------|---------|
| 修改核心数据流 | 数据流向变更、新增存储 | 1. 创建 ADR<br>2. 架构师评审<br>3. 创建 CR-XXX<br>4. 项目负责人批准 |
| 变更数据库 Schema | 增/删/改表、字段类型变更 | 1. 编写 Migration<br>2. DBA/架构师评审<br>3. 制定回滚方案<br>4. 变更窗口执行 |
| 调整服务边界 | 拆分/合并服务、变更 RPC 契约 | 1. 完整影响分析<br>2. 所有受影响团队确认<br>3. 分阶段迁移计划 |
| 修改核心算法/业务规则 | 影响业务核心逻辑 | 1. 业务方确认<br>2. 完整回归测试<br>3. 灰度发布方案 |

---

### L4 - 基础设施/安全（禁止 AI 直接操作）

| 操作 | 原因 | 正确流程 |
|------|------|---------|
| 修改 `.github/workflows/` | 影响全项目 CI/CD | 人工编辑 + 流水线验证 |
| 修改 `docker-compose.yml` / `Dockerfile` | 影响构建/部署 | 运维审核 + 分环境验证 |
| 修改 `deploy/` / `infra/` | 生产环境配置 | GitOps 流程 + 变更窗口 |
| 引入新外部依赖 | 供应链安全、许可证、维护成本 | 1. 提交 CR<br>2. 安全扫描<br>3. 许可证合规检查<br>4. 架构师批准 |
| 修改 `.claude/settings.json` | 改变 AI 权限边界 | **仅限人工修改** |
| 处理密钥/证书/凭据 | 安全红线 | 仅限密钥管理系统 / 人工操作 |

---

### L5 - 破坏性/不可逆（绝对禁止 AI）

| 操作 | 执行主体 |
|------|---------|
| `git push --force` / `git reset --hard` (远程) | 仅限维护者紧急处理 |
| `DROP TABLE` / `TRUNCATE` (生产) | 仅限 DBA + 双人确认 |
| 删除整个模块/服务 | 项目负责人决策 + 归档流程 |
| 修改 `main` 分支保护规则 | 仅限仓库 Admin |
| 覆盖生产环境配置 | 仅限发布流程 |

## 四、AI 遇到越权操作时的处理流程

```
AI 识别到需要 L3/L4/L5 权限的操作
    ↓
1. 立即停止执行
    ↓
2. 在 SESSION-STATE.md 记录待决策项
   | D# | 问题 | 所需权限级别 | 建议方案 | 决策状态 |
   | D1 | 需要修改数据库 Schema | L3 | 编写 Migration + ADR | ⬜ 待审批 |
    ↓
3. 向人工报告：
   - 当前任务：T-XXX
   - 卡在步骤：X
   - 需要决策：具体描述
   - 建议方案：A/B/C
    ↓
4. 等待人工决策（不得自行继续）
    ↓
5. 人工决策后：
   - 批准 → 更新 SESSION-STATE.md 决策列 → AI 继续执行
   - 拒绝 → AI 记录拒绝原因 → 寻找替代方案或标记任务阻塞
   - 要求补充 → AI 补充材料 → 重新提交审批
```

## 五、权限矩阵速查表

| 场景 | 权限级别 | AI 能做吗？ | 需要什么？ |
|------|---------|------------|-----------|
| 修复一个函数的 Bug | L1 | ✅ 能 | 任务存在 + 测试通过 |
| 新增一个 API 接口 | L2 | ⚠️ 有条件 | 设计文档 + 任务规划 |
| 修改 API 响应格式 | L3 | 🔴 不能直接做 | ADR + CR + 人工批准 |
| 升级 Go 版本 | L4 | 🔴 禁止 | 安全审查 + 运维执行 |
| 添加 Redis 依赖 | L4 | 🔴 禁止 | CR + 安全扫描 + 架构师批准 |
| 紧急回滚生产版本 | L5 | 🔴 绝对禁止 | 仅限人工发布流程 |
| 重构用户认证模块 | L3 | 🔴 不能直接做 | 完整设计 + 评审 + 分阶段 |
| 修改 Lint 规则 | L2 | ⚠️ 有条件 | 团队约定 + 统一应用 |
| 更新 README | L1 | ✅ 能 | 任务要求 |

## 六、权限升级/降级机制

### 升级（扩大 AI 权限）
- **条件**：连续 N 个 Sprint 无严重违规、人工审批通过率 100%
- **流程**：项目负责人提交申请 → 更新 `.claude/settings.json` → 记录变更日志
- **原则**：默认最小权限，按需最小化开放

### 降级（收回 AI 权限）
- **触发**：出现 L3+ 级别违规、连续 3 次验收失败、安全事件
- **流程**：立即修改 `.claude/settings.json` 收回权限 → 根因分析 → 整改验证后恢复
- **原则**：安全第一，宁可慢不可乱

## 七、工具配置映射（`.claude/settings.json`）

```json
{
  "permissions": {
    "allow": ["Read", "Glob", "Grep", "Task", "WebFetch", "WebSearch"],
    "deny": ["Write(.env*)", "Write(.secret*)", "Write(deploy/**)", "Bash(sudo *)", "Bash(git push --force *)"],
    "ask": ["Write(src/**)", "Write(tests/**)", "Edit(**)", "Bash(go mod *)", "Bash(git push *)"]
  }
}
```

| 配置项 | 对应权限级别 | 说明 |
|--------|-------------|------|
| `allow` | L0 | 无风险只读操作 |
| `ask` | L1-L2 | 需要人工确认的编码操作 |
| `deny` | L4-L5 | 绝对禁止的高危操作 |
