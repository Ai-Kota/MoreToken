# 2026-09-20 · auto:reasoning 全线 503（付费档的能力空洞）

> **一句话**：网关把一个瞬态抖动当成了事实，切进付费档；而付费档里没有 reasoning 模型，

- **进程日志断链**（14:54 起的进程，日志文件停在 14:41）⇒ 45 分钟的 stderr 一条不落盘
- **错误原文没留下**（用户只报了"报错了"）

**可复用的定位路径**：

1. 看 `/decisions` 里的**状态机事件**，不是看错误——错误根本没记
2. **用"翻档前后免费池仍在出 200"证伪"免费层挂了"**

   kinds 无 reasoning ⇒ 门控先删免费、`HasKind` 再删付费 ⇒ 候选空集 ⇒ `tried 0`

   **在那之前它只是推断**

## 3. 根因（第一性）

### 3.1 兜底被实现成了过滤器

`internal/router/router.go` 的 `paidOnly()`：

```go
// 候选集：[agnes-anthropic(免费,reasoning), xkiro-anthropic(免费,reasoning), agnes-paid-anthropic]
// 进"付费档"后：
cands = paidOnly(cands)   // → [agnes-paid-anthropic]   —— 免费被删掉了
// 再经 HasKind(reasoning) 过滤：
                          // → []                       —— 空集
```

**兜底的候选集成了主力的真子集。** 任何 fallback 的第一性要求是
`fallback ⊇ primary`；违反它，触发兜底**唯一的效果就是减少可用性**。

### 3.2 兜底本来就不需要"档位"

`candidates()` 返回的就是 `free → paid` 的**有序链**，`Route` 的循环遇到不可用候选
就 `continue` / `markBackoff` 往后走——**"这一次免费挂了就这一次用付费"是原生行为**。

层门控的**唯一净效果**，是把付费从"这一次请求的备选"提升为"接下来三分钟的首选"。
那不是兜底机制，是**把应急升格为主力的机制**。

### 3.3 防抖装反了

| 方向 | 需要什么证据 | 判错的代价 |
|---|---|---|
| FREE → PAID | **一次**（零防抖） | **整层能力黑洞 3 分钟** |
| PAID → FREE | 连续健康 ≥3 分钟 | 多试一次免费池 |

代价大的转移门槛最低，代价小的门槛最高。

## 4. 修法（`8f94ad3`）

**删掉门控**（`paidOnly` / `TierGate` / `WithTierGate` / `gate` 字段 / `Route` 里的门控分支）。
候选顺序**恒为** free → paid，档位不再参与任何路由决策。

状态机降为**观测器**：只做两件事——定向探活（给被隔离的池一条复活通道）+ 平滑上报。
它的防抖留着（对"给人看的信号"降噪是对的），但**不再有权拦住任何一个请求**。

## 6. 牵出的四个问题（修一层露一层）

主线修完，又露出四条。**每一条都是独立可证伪的缺陷**，不是同一件事的重复：

### 6.1 `503` 不留痕（`T-016`，已修）

`proxy.go` 的 `if ferr != nil` 分支**在 `Record` 之前就 return 了**，
而它上面的注释写着"决策日志已留痕"。

**注释承诺的调用点，代码里找不到**——本仓在 `TROUBLESHOOTING §2` 已经栽过一次同款。

代价：事故那段时间在 `/decisions` 里是空白的，**是什么请求把免费池判死的，至今【未核实】**。

真身验证：发一条"kind 无人提供"的请求（候选集在路由前就是空的，不碰任何上游）：

```
HTTP 503
/decisions → {"provider_id":"router","reason":"router: no anthropic provider
               offers kind \"no-such-kind\"","status":503,"want":"auto:no-such-kind"}
```

**这就是事故里缺失的那一行。**

### 6.2 `staleness` 假绿（`T-016`，已修）

```
$ dev-fleet staleness
  ✓  moretoken  已生效（bin 16:00:07）
$ Get-CimInstance Win32_Process ...   # 实际在跑的进程
  CreationDate 14:54:03               ← 早于 bin 一个多小时
```

闸只比"源码 vs bin"，**不看运行进程加载的是哪个 bin**。

**假绿比空白更贵**：空白让人继续查，假绿让人基于错误前提收工——当时我差点信了。

修法：补第二个判据（进程启动时刻早于 bin ⇒ 待生效），做成纯函数 + **只严不松**的性质测试。

### 6.3 模型维度是死的（`68f9b06`，已修）

准备做"从上游目录自动纳新"时，**先验了一件事**：纳进来的模型路由用不用得上？

答案是**用不上**。`tryCandidate` 在 key 循环**之前**只解析一次模型，
然后只用它轮 3 把 key——**同 provider 的其余模型永远不会被尝试**。

实测：一个带可用备用模型的 provider，首选 5xx 时请求整体失败
（`router: exhausted anthropic candidates (tried 1, limit 4)`）。

⇒ **池子的维度是 (provider × key)，模型维度是死的。往 config 里加 24 个免费模型，净收益是 0。**
⇒ 如果先写 harvester，交付的就是个装饰品。

### 6.4 `403` 被当成凭据问题（`fdb3fde`，已修）

判决性实验（两个上游结果一致）：

| 组合 | xkiro | agnes |
|---|---|---|
| 好 key + 好模型 | 200 | 200 |
| 好 key + **无权模型** | **403** | **403** |
| **垃圾 key** + 好模型 | **401** | **401** |

401/403 曾同归 `FailAuth` ⇒ 路由对 403 也 `RecordDead`（长禁该 key **1 小时**）
⇒ **一个无权模型进 config，会把该 provider 的 key 逐个禁光、整层下线一小时**
（33 把 key × 1h，而正确的代价是 0 把 key × 60s）。

修法：403 拆成 `FailDenied`，按模型级处理（换模型，不碰 key）；401 仍隔离该 key。

## 7. 沉淀下来的原则

这案子反复用到同一批判据。它们是可迁移的，比具体修法耐用：

| # | 原则 | 出处 |
|---|---|---|
| 1 | **fallback 的候选集必须 ⊇ primary 的**。违反它，触发兜底的唯一效果是减少可用性 | §3.1 |
| 2 | **吸收即销毁证据**。网关越擅长本职工作就越不透明 ⇒ 失败必须在**带外**留一等公民记录 | §6.1 |
| 3 | **假绿比空白更贵**。空白让人去查，假绿让人基于错误前提收工 | §6.2 |
| 4 | **粗粒度机制重造细粒度机制，是单点故障的温床**。池级退避（60s/per-provider/自愈）已解决的事，不该再用全局档位重做一遍 | §3.2 |
| 5 | **静态性质才能穷举检查**。运行时状态只能改候选的**顺序与跳过**，不能改**存在**——守住了这条，能力面就是静态的，就能在**部署前**穷举断言 | `T-018` 的供给面断言 |
| 6 | **先查实再设计**。harvest 前先问"纳进来用得上吗"，救回了一整个交付 | §6.3 |
| 7 | **排序先验 ≠ 过滤器**。`:free` 优先实测是排序（错了只是慢），当成过滤器就会把"上游换了标记习惯"变成静默的能力损失 | `T-018` |
| 8 | **代价决定门槛**。误进兜底 = 整层黑洞，误回免费 = 一次无用尝试 ⇒ 贵的转移门槛必须**更高** | §3.3 |

## 8. 方法（比结论耐用）

| 方法 | 用在哪 | 要点 |
|---|---|---|
| **变异检验** | 每一条回归测试 | 把新测试对着**旧代码**跑一遍，确认它失败，且**症状与现场逐字一致**。没做过的回归测试等于没写 |
| **真身验证** | 每个交付 | 编译通过 ≠ 能运行。新 bin 起旁路端口、走真凭据真上游 |
| **对照实验** | 定位 | 只换一个变量（假模型名 503/404 vs 真名 200），差异即证据 |
| **判决性实验** | 反驳自己的假设 | 提"403 = 凭据问题"前，先拿**垃圾 key** 打一发看回什么 |
| **留上游原文** | 每一次失败 | 顺手改写成"上游不可用"就把线索丢了 |
