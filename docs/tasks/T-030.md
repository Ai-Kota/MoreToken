# T-030: #12 开机链重启验证——带外证据自动固定

> 起因：T-026 验收唯一悬置项 #12（机器重启后网关自动在跑）。用户指令"你来重启吧"。
> 重启会杀掉当前会话——**不带记录就重启 = 亲手抹现场**（T-016 血账原话）。
> 所以先把验证器布成登录时自动跑、证据自动落盘，再执行重启。

**允许修改文件**：docker/**, docs/**, C:/Users/aimly/AppData/Roaming/Microsoft/Windows/Start Menu/Programs/Startup/moretoken-boot-verify.vbs

## 设计

1. **docker/boot-verify.sh**（新）：登录时自动执行的验证器，判据全部机器可查：
   - 记录系统启动时刻（LastBootUpTime）作为"容器是自己起来的"基准
   - 轮询 docker daemon 就绪（≤300s，AutoStart 登录项 → 引擎要 30-90s）
   - 轮询容器 running/healthy（≤180s）+ 记 StartedAt
   - 端点三连：/health=200（豁免）、/v1/models 无 token=401（鉴权存活）
   - cc-ft 链路等价：vault get laptop-cc → 带 token=200
   - 旁证：freellm 群计数（Docker 自启面整体健康）
   - 全部 append 落 `docker/runtime/boot-verify.log`（带时间戳，FAIL 附恢复命令）
2. **Startup 隐藏宿主**：`moretoken-boot-verify.vbs`（Startup 文件夹，ASCII-only，
   window style 0——对齐本机防闪窗纪律；schtasks onlogon 需管理员，Startup 不需要，
   且 dev-fleet-up.lnk 已有先例）
3. 重启前**基线跑一次**（证明验证器本身工作 + 日志留基线条目；真证据 = 重启后
   BOOT 时刻更新的那一段）

## 验收判据

- [x] boot-verify.sh 基线跑通（重启前全 PASS，证明脚本无 bug）
- [x] vbs 入 Startup、bash -n 过、提交落库（重启前证据链已入库）
- [ ] **重启后**：boot-verify.log 出现 BOOT=新时刻 的段落且 #12a/b/c 全 PASS（下个会话核销）
- [ ] 重启后 dev-fleet monitor 读新配置：/doctor 401 噪音消失（决策日志观察）

## 边界

- 重启后需要**登录一次**（Docker AutoStart 是登录项——T-026 已记录例外 1）
- 本会话会被重启杀掉：结果不靠会话记忆，全靠 boot-verify.log（带外）
