# T-026: Docker 化部署（宿主解析 vault → 容器运行；开机零手动）

> 起因：2026-09-29 用户定性——**dev-fleet 是鸡肋、随时废弃；freellm 8 容器稳定性远超它；
> 要求用 Docker 部署 moretoken，安全与稳定性问题全部妥善解决。**
> 核心矛盾：90 把 key 是 `vault:` 指针，启动时 exec **Windows** vault.exe 解析，Linux 容器内不可用。
> 骨架解法：**解析留宿主、运行进容器**——宿主用已测试的 ResolveKeys 把指针解析成完整 config，
> 经管道直投 Docker 命名卷；容器只消费成品。T-024"校验面零 vault 依赖"使 token 鉴权容器内原生可用。

## 对抗评审吸收的 3 个阻断级缺陷（Plan agent 实证）

1. **卷名三方不一致**（compose external 按字面名找、脚本建的是前缀名）→ 顶层 `name: moretoken` + external 卷名写全 `moretoken_moretoken-run`，脚本字面对齐
2. **容器 CMD 缺 `-config/-tokens-file`** → 默认推导指向卷内不存在文件 → LoadStore 空快照 → **静默不鉴权且全绿**（最坏失败模式）→ CMD 写死两 flag + entrypoint 双文件检查 + buildAuthStore fail-closed
3. **tokens.json 单文件 bind-mount** → 宿主 revoke 走 tmp+rename 换 inode → 容器钉死旧 inode → **吊销永久失效且静默** → 改**目录 ro 挂载**，revoke→401 传播 <5s 列为必过断言

```
│  ├ -token-gen/revoke/...  │  投递卷  │  │   (命名卷 0600, 明文只在卷)│
│  │  写 docker/runtime/    │          │  ├ /run/mt-tokens/ (目录 ro │
│  │  tokens.json (唯一写者) │          │  │   ← docker/runtime)      │
│  └ mt-deploy.sh 编排      │          │  └ /run/secrets/nats/creds  │
│ dev-fleet: 冲突条目停用    │          │ NATS: 镜像内 linux nats CLI │

```

开机链：登录 → Docker Desktop(AutoStart✓) → daemon 拉 `restart: always` 容器 → 卷持久（config 已在卷，**无需 vault**）→ cc-ft 可用。**零手动**。

## 安全姿态（诚实版，写进文档）

解析后明文 key 存 Docker 命名卷，物理落 Docker Desktop WSL2 数据盘（vhdx）。保护级别 = **不进 git/仓库、0600、读取需 docker 权限、at-rest 靠 BitLocker**（验证查状态）。**优于** freellm（明文 0644 在仓库）。**不是"不落盘"**——文档措辞按此写，不撒谎。tokens.json 只有哈希+指针。端口只绑 127.0.0.1。T-024 鉴权照常。

**token 单写者原则**：宿主 CLI 是 tokens.json 唯一写者；容器目录 ro 挂载 + **禁 last_used 回写**（消双写者"吊销复活"竞态；代价 = last_used 停更，runbook 记录）。

## 代码改动（全部带测试）

1. `-materialize-config <path|->`（main.go）：Load→ResolveKeys→`unresolved>0` 列明细 exit 1（部署闸）→MarshalIndent；日志只进 stderr；EPIPE 显式非零退出。测试：round-trip、输出无 vault:/env: 残留、stdout 纯净
2. tokens fail-closed（buildAuthStore）：显式 `-tokens-file` 而文件不存在 → Fatalf（现状静默空快照=不鉴权）
3. TouchAsync 开关：`WithTouchDisabled()` option + main 读 `MORETOKEN_AUTH_TOUCH=off`（compose 设）→ ro 挂载下不刷 EROFS WARN
4. runDoctorClient 防假绿：非 200/503（如 401）→ exit 2 + 明说"被鉴权挡/配置错"，不回落"ok"（T-016 铁律）

## 新文件 docker/

- **Dockerfile**：多阶段。builder golang:1.25-alpine + `ENV GOWORK=off`（仓根有 go.work）+ CGO_ENABLED=0；runtime alpine:3.21 + ca-certificates + tzdata + nats CLI（natsio/natscli release linux-amd64，**pin 版本+sha256** + `RUN nats --version` 证 musl 兼容）；非 root uid 10001；`ENV HOME=/tmp`；预建三挂载点；ENTRYPOINT entrypoint.sh + CMD 写死两 flag
- **entrypoint.sh**：config.json / tokens.json 任一缺失或不可读 → 红字指路 mt-deploy.sh + exit 非零（绝不静默裸奔）
- **docker-compose.yml**：顶层 `name: moretoken`；`restart: always`（unless-stopped 有一次 stop 就跨重启静默失踪的陷阱）；`read_only: true`+`tmpfs: /tmp`；`no-new-privileges`；ports `127.0.0.1:8462:8462`；volumes：`moretoken-run`(external:true,name:moretoken_moretoken-run)→/run/moretoken，`../docker/runtime:/run/mt-tokens:ro`（目录），bridge.creds→/run/secrets/nats/:ro；env NATS_*+NATS_BIN=/usr/local/bin/nats+MORETOKEN_AUTH_TOUCH=off+TZ；healthcheck wget /health 30s/5s/20s/3；logging 10m×3；build{context:..,dockerfile:docker/Dockerfile}
- **mt-deploy.sh**（Git Bash，`set -euo pipefail`，幂等）：①pre-flight 三 bind 源存在**且是文件**（防 Docker 缺失源自动建目录）+ 探测 :8462 占用 ②宿主 go build ③`-check` 闸 ④`docker volume create moretoken_moretoken-run` ⑤materialize 管道投递 `.new`+非空校验+卷内原子 mv（管道断不毁现役）⑥`compose up -d --build` ⑦调 mt-verify.sh
- **mt-verify.sh**：下方验证矩阵全断言化、可重跑
- **docker/README.md**：日常操作、token 发放/吊销两姿势、代谢（harvest 宿主跑+重跑 deploy）、三条开机链例外、doctor 判据迁移期失效说明

## 真身验证结果（2026-09-29 首部署，全过）

镜像构建成功（多阶段；nats CLI sha256 校验过、`nats --version`=0.4.0 musl 兼容；go build 4.8s；entrypoint sed 去 CRLF）。`mt-verify.sh` **15 PASS / 0 FAIL**：

- #1-2b `/health` 豁免 200；`/v1/models`、`/decisions` 无 token 401
- #3-3b Bearer + x-api-key 带 token 均 200
- #4 容器内 uid=10001 可读 tokens.json + nats creds
- #5-5b 真实 chat completion（auto:general）200，决策日志带 `auth:"verify-probe"`（I11 谁发的可答）
- **#6 吊销 2.5s 内容器侧 401**（目录挂载 rename 传播——评审 S1 的决定性证据；单文件挂载会永久失效）
- #7 `docker restart` 恢复健康
- **#8 进程自然退出（TERM PID1）→ restart:always 自动拉起（RestartCount 0→1，2s 内）**
- #9 宿主订阅 `aimly.system.freetier.status` 收到容器发布的池快照（agnes 33/xkiro 11 keys，tier free）
- #10 `dev-fleet guard` 通过（无 :8462 违规；free-tier-aggregator 已停用）
- cc-ft 真实链路：`vault env` 注入 laptop-cc → 容器 `/v1/models` 200

**验证脚本自身修的两个测试 bug**（非部署缺陷）：① #8 原用 `docker kill`——那是**手动停止**，Docker 语义下 `restart:always` 不立即重启（要到 daemon 重启），改用 `docker exec kill -TERM 1`（自然退出）才测到真重启策略；② #6 用了 Git Bash 没有的 `bc`；③ #9 窗口 35s 太短撞上重启周期，放宽到 70s 覆盖两个 30s tick。

**首部署暴露的真问题**：`restart:always` 对 `docker kill`（手动）不立即重启是 Docker 既定语义——开机自启靠的是 **daemon 重启时重新应用 always 策略**（#12 机器重启验证），不是靠 kill 自愈。已在 docker/README 开机链三条例外里写明。
