# T-024: 网关 Token 鉴权（vault 指针发放 + 生成/吊销/过期/热加载）

> 起因：2026-09-29 会话。网关监听所有网卡且**零入站鉴权**（`internal/proxy/proxy.go`
> 全文无任何 Authorization/x-api-key 校验）——局域网内任何机器都能白用背后 90 把上游 key。
> 用户三步定案：①要加 token 校验 ②要"生成/废弃机制"控风险 ③token 存 vault 密码墙，
> 智能体用**指针**访问（对齐本仓既有铁律：*"外面只放指针，明文只在墙里"*，config.go:8）。

**允许修改文件**：internal/**, main.go, docs/**, config/**, scripts/**

---

## 1. 目标与非目标

**目标**
1. 入站请求必须携带有效 token，否则 401；`/health` 豁免（dev-fleet 存活探针依赖，见 proxy.go:98-104）。
2. Token 全生命周期管理：生成（明文直入 vault，永不落盘/回显）、列出、吊销、轮换、默认过期。
3. 每客户端独立 token → 单点泄露只废一个，吊销秒级生效（热加载，不重启）。
4. 鉴权留痕：`/decisions` 记录 token name（谁发的），tokens.json 回写 last_used。
5. 向后兼容：未配置任何 token 时行为与现在完全一致（本机开发零打扰）。

**非目标**
- IP 白名单、速率限制（后续任务）。
- 跨机 vault 指针解析（vault 是本机墙；远程智能体经安全通道一次性投递明文，边界见 §8）。
- 修改上游 key 的解析路径（`vault:` 前缀机制原样复用，不动）。

## 2. 威胁模型

| # | 威胁 | 对策 |
|---|------|------|
| TH1 | LAN 内陌生机器直连 :8462 白嫖上游 key | 中间件 401 拒绝无 token 请求 |
| TH2 | 明文 token 落盘扩散（config/.env/备份/git） | 只存 SHA-256 哈希；明文只存在于 vault 与客户端进程内存 |
| TH3 | 生成时刻泄露（终端回显被抄/录屏/shell history） | `-token-gen` **不回显明文**，管道直写 `vault put`；取用靠 `vault env` 注入 |
| TH4 | token 泄露后长期失血 | 默认 30 天过期 + `-token-revoke` 热生效 |
| TH5 | 分不清谁在用（审计缺失） | 每客户端一个 name；决策日志记 name；last_used 回写 |
| TH6 | 时序侧信道比对 token | `crypto/subtle.ConstantTimeCompare`（对哈希后的定长摘要比较） |
| TH7 | 鉴权依赖引入新故障面（vault 挂了网关起不来） | 校验只用本地 tokens.json 哈希，**运行路径零 vault 依赖**；vault 只是发放渠道 |
| TH8 | 探针被鉴权挡死 → dev-fleet 重启永动机 | `/health` 永久豁免（与 proxy.go 里 /doctor 独立通道的既有设计同理） |

## 3. 总体架构

```
                        ┌─ 发放面（低频，CLI）──────────────────────┐
 moretoken -token-gen ──┤ 生成 mt_* → vault put（exec，管道）        │
                        │ tokens.json ← {name, vault_path, hash,    │
                        │                expires, revoked}          │
                        └───────────────────────────────────────────┘
                                        │ mtime 热加载
                        ┌─ 校验面（每请求，网关内）─────────────────┐
 智能体 ── vault env 注入 ──► Authorization: Bearer mt_* / x-api-key │
                        │ auth.Store.Verify(hash 比对, 过期, 吊销)   │
                        │   ├─ 通过 → mux（/v1/*、/decisions）      │
                        │   └─ 拒绝 → 401 + 决策日志留痕            │
                        │ /health 直通（豁免）                       │
                        └───────────────────────────────────────────┘
```

两面分离是关键：**校验面不碰 vault**（TH7），**发放面不碰网络**。

## 4. 数据结构

### 4.1 `config/tokens.json`（新文件，git 可入库——无明文）

```json
{
  "tokens": [
    {
      "name": "dify-lan",
      "prefix": "mt_9xKq2v",
      "hash": "sha256:<hex64>",
      "vault_path": "moretoken/tokens/dify-lan",
      "created": "2026-09-29T08:30:00+08:00",
      "expires": "2026-10-29T08:30:00+08:00",
      "revoked": false,
      "last_used": null
    }
  ]
}
```

- `name`：唯一标识（CLI 参数、审计维度）。重名生成 → 报错拒绝。
- `prefix`：明文前 8 字符，仅人眼识别用（`mt_` + 5 字符），不可反推。
- `hash`：SHA-256(明文) hex。**校验只比哈希**，明文永不进网关内存以外的地方。
- `vault_path`：指针。为空 = 简化模式（`-token-plain` 显式选择，回显一次明文，供无 vault 场景）。
- `expires`：空 = 永不过期（须 `-token-ttl 0` 显式选择）；默认 30 天。
- `last_used`：网关校验通过后**异步回写**（写失败只记日志不拒请求——审计字段不得反噬可用性）。

### 4.2 `config.Config` 新增字段（internal/config/config.go）

```go
type Config struct {
    Listen     string     `json:"listen"`
    AuthToken  string     `json:"auth_token,omitempty"`  // 兼容：单 token 简化模式，支持 env:/vault: 前缀
    Providers  []Provider `json:"providers"`
    ...
}
```

**优先级**：`tokens.json` 存在且有活跃条目 ⇒ 多 token 模式；否则 `auth_token` 非空 ⇒ 单 token 模式（复用既有 ResolveKeys 的 env:/vault: 解析）；两者皆空 ⇒ 不鉴权（现状）。

### 4.3 Token 明文格式

`mt_` + 32 字节 CSPRNG（`crypto/rand`）的 base62 编码（约 43 字符）。`mt_` 前缀便于泄露扫描器识别（对齐 GitHub secret scanning 惯例）。

## 5. 模块设计

### 5.1 `internal/auth`（新包）

```go
// Store 是校验面的全部。零 vault 依赖（TH7）。
type Store struct { ... }

// LoadStore 读 tokens.json（不存在 → 空 Store，不报错）。
func LoadStore(path string) (*Store, error)

// Store.Verify 输入明文 token，返回命中的条目名。
// 流程：SHA-256 → 遍历条目 → ConstantTimeCompare(hash)
//   → 命中后再查 revoked / expires（先比哈希再查状态：状态检查不得成为时序 oracle）
// 空 Store（无任何 token 配置）→ Verify 恒通过，返回 ""（兼容模式）。
func (s *Store) Verify(plain string) (name string, ok bool)

// Store.ReloadIfChanged 每次 Verify 前调用：mtime 变了才重读（热加载，无 fsnotify）。
// 重读失败 → 保留旧快照 + 记日志（坏文件不得把在线网关打瞎）。
func (s *Store) ReloadIfChanged() 

// GenToken 生成明文（唯一一处出口，发放面专用）。
func GenToken() (plain string, err error)

// Hash / Prefix 纯函数。
func Hash(plain string) string
func Prefix(plain string) string

// VaultWriter 抽象 exec vault put（镜像 config.defaultVaultGet 的注入式设计，测试 mock）。
type VaultWriter interface { Put(path, plain string) error }

// Issue = GenToken + VaultWriter.Put + tokens.json 追加（一个事务语义：
// vault 写成功才落 tokens.json；tokens.json 写失败 → vault delete 回滚）。
func Issue(store *Store, vw VaultWriter, name, vaultPath string, ttl time.Duration, now time.Time) (*Entry, error)

// Revoke / Rotate：按 name 标 revoked / 生成新条目+废旧条目。
func Revoke(storePath, name string) error
func Rotate(storePath string, vw VaultWriter, name string, ttl time.Duration, now time.Time) (*Entry, error)
```

**时钟注入**：过期判定用注入的 `now`（测试给 fake clock，对齐 TEST-MATRIX §0 既有手段）。

**热加载判据**：`os.Stat(path).ModTime()`。Windows mtime 分辨率 ~100ns，够用；同一秒内两次修改的极端场景由 revoke/rotate 走"写文件+进程内直接生效"双通道兜底（CLI 与网关同机时，CLI 写完提示"网关最迟下次请求生效"）。

### 5.2 `internal/proxy` 中间件

```go
func (s *Server) Handler() http.Handler {
    mux := http.NewServeMux()
    ... // 现有路由不动
    if s.auth == nil { return mux }        // 未配置 → 原样返回（兼容）
    return s.authMiddleware(mux)
}

func (s *Server) authMiddleware(next http.Handler) http.Handler {
    return func(w, req) {
        if req.URL.Path == "/health" { next.ServeHTTP(w, req); return }  // TH8 豁免
        s.auth.ReloadIfChanged()
        tok := extractToken(req)   // Authorization: Bearer x → x；否则 x-api-key 头
        name, ok := s.auth.Verify(tok)
        if !ok {
            s.declog.Record(...status 401, reason "auth: missing/invalid/expired/revoked"...留痕)
            writeJSON(w, 401, openai 或 anthropic 形状的 error body——按端点协议回错误格式)
            return
        }
        req = req.WithContext(context.WithValue(req.Context(), authNameKey, name))
        s.auth.TouchAsync(name)    // last_used 回写（异步、失败不拒）
        next.ServeHTTP(w, req)
    }
}
```

细节规矩：
- **401 body 按端点协议成形**：`/v1/messages` 回 anthropic 错误 JSON，`/v1/chat/completions` 回 openai 错误 JSON（客户端 SDK 才认得，对齐 T-009 修 401 透传的同款教训）。
- `/v1/models`、`/decisions`、`/doctor` 一并保护（`/decisions` 含路由情报，`/doctor` 供 cli 探针——探针在本机，token 从 vault 取即可；若 dev-fleet 探针脚本需要，`/doctor` 可后续加豁免，**默认保护，宁严勿松**）。
- 决策日志新增 `auth` 字段（name 或 "anonymous-rejected"），拒绝也 Record（T-016 教训：吸收即销毁证据，拒绝必须留痕）。

### 5.3 `main.go` CLI 子命令（对齐 -check/-harvest 布尔开关风格）

| 开关 | 行为 |
|---|---|
| `-token-gen` | 生成。配合 `-token-name`（必填）、`-token-ttl`（默认 720h；0=永不过期）、`-token-plain`（无 vault 简化模式，回显一次） |
| `-token-list` | 表格：NAME / PREFIX / CREATED / LAST-USED / EXPIRES / STATUS(active·expired·revoked) / VAULT |
| `-token-revoke` | 吊销（`-token-name` 指定）。热生效提示 |
| `-token-rotate` | 轮换：新 token 入 vault（vault 自动留 history）+ 旧条目标 revoked |
| `-tokens-file` | tokens.json 路径（默认 config 同目录 tokens.json） |

所有子命令**做完即退**（exit code 语义对齐 -check）。vault exec 失败 → 明确报错退出，**不静默降级**（发放面失败必须可见）。

### 5.4 vault 集成（发放面）

`defaultVaultPut`：`vault.exe put <path> --data @-`（stdin 管道传明文，**不上命令行参数**——进程列表可见 argv，`--data <明文>` 会泄露给同机所有用户；stdin 不会）。vault 路径默认 `E:\AImlyForge\tools\PUBLIC\vault\bin\vault.exe`，`VAULT_BIN` 覆盖（与 config.DefaultVaultBin 同源）。

## 10. 决策记录（本档定案，不再摇摆）

| 争议点 | 决定 | 理由 |
|--------|------|------|
| 校验时查不查 vault | **不查** | TH7：运行路径零外部依赖；vault 只是发放渠道 |
| /doctor 豁免与否 | **保护** | 宁严勿松；本机探针可从 vault 取 token |
