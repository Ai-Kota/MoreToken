## 第一性原理

网关的职责就是**吸收失败**——重试、冷却、退避、兜底，全都是"让调用方看不见故障"。
但**吸收即销毁证据**：一次被成功兜住的失败，在调用方看来与"什么都没发生"完全一样。

矛盾是天生的：**它越擅长本职工作，就越不透明。** 唯一解法是**带外记录**——
证据必须走一条不在吸收路径上的一等公民通道。

两条推论，本任务逐条落地：

- **P1｜每一次被吸收的失败，都必须在带外留一条一等公民记录。** 否则"可用"不可验证。
- **P2｜观测通道的可靠性必须 ≥ 被观测系统；假绿比空白更贵。**
  空白让人去查，假绿让人放心。

## 问题（均已实测，非推断）

### 1. 503 不留痕（P1）

2026-09-20 15:31:49–15:34:49 那段事故窗口，在 `/decisions` 里是**一行都没有**。
`proxy.go` 的 `if ferr != nil` 分支**在 Record 之前就 return 了**——
而它上面的注释写着"决策日志已留痕"。**注释承诺的调用点，代码里找不到**（本仓 §2 栽过同款）。

代价：那段时间发生了什么、是什么请求把免费池判死的，**至今是【未核实】**，只能靠
翻档前后恰好各有一条 200 当对照反推。

### 2. `staleness` 假绿（P2）

```
$ dev-fleet staleness
  ✓  moretoken     已生效（bin 2026-09-20T16:00:07）
$ Get-CimInstance Win32_Process ...   # 实际在跑的进程
  ProcessId 33648  CreationDate 2026/9/20 14:54:03      ← 早于 bin 一个多小时
```

`checkStaleness` 只比 **源码 mtime vs bin mtime**（`staleness.go` 的 `Stale` 字段），
**不看运行中的进程加载的是哪个 bin**。于是"bin 更新了、进程还跑着旧的"这一格，
它报 ✓。

判据（人侧，已写入 `TROUBLESHOOTING §8-6`）：进程 `CreationDate` 必须**晚于** bin mtime。

**假绿比空白更贵**：空白会让人继续查，假绿会让人基于错误前提收工——今天我自己就差点信了。

## 改法

### 1. 503 留痕（已完成）

`proxy.go` 的 503 分支补 `declog.Record`：`provider_id="router"`（没有任何 provider
服务成功，决策在路由层就终止）、`reason=ferr.Error()`、`status=503`、`want=请求的 model 原文`。
同时改掉那条假注释。

### 2. staleness 补第二个判据（本任务实现）

`stalenessVerdict(srcT, binT, procT, haveProc)` —— 拆成**纯函数**以便单测：

| 条件 | 结论 |
|---|---|
| `srcT > binT` | 【待生效】源码新于二进制（既有判据，不动） |
| `haveProc && procT.Before(binT)` | 【待生效】进程启动早于二进制 ⇒ 跑的是旧 bin（**新增**） |
| 其余 | 已生效 |

**安全性质：新判据只能让闸更严，不能让闸更松。** 取不到进程时刻（未运行/查询失败）时
不据此判 stale —— 既有判据照常生效，绝不因新逻辑放宽。

进程时刻一次 PowerShell 批量取（`Get-CimInstance Win32_Process` + 显式 ISO 格式化），
沿用 `guard.go` 的 `cmdlines` 同款做法（一次调用，不每服务一 spawn）。

### 真身验证 1：503 留痕（生产实测 2026-09-20 16:27:51）

发一条"kind 无人提供"的请求——它**不会碰任何上游**（候选集在路由前就是空的），
所以可以在生产上安全地走一遍这条路径：

```
$ curl -X POST :8462/v1/messages -d '{"model":"auto:no-such-kind",...}'
HTTP 503
$ curl :8462/decisions?n=2
[..., {"at":"2026-09-20T16:27:51.2736662+08:00","provider_id":"router","retried":false,
       "reason":"router: no anthropic provider offers kind \"no-such-kind\"",
       "status":503,"want":"auto:no-such-kind"}]
```

**这就是事故里缺失的那一行。** 再看不出"是什么请求、因为什么、被谁拒"，才是不正常的。
