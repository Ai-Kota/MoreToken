### 计划外发现并一并修复

- **I9 凭据隔离（新增不变量）**：`provider.go` 原把 401/403 归入 `FailNone`（"4xx 透传"），
  路由判 `done=true` 把 401 原样甩给客户端——**一个失效的 key 会打死整个池**，
  多 key 轮换的核心承诺落空。改为新增 `FailAuth` 分类 + `pool.RecordDead`（长禁 1h），
  换池内下一把而非透传。
- **`/health` 的 `keys` 一直在撒谎**：返回的是配置原始条数（含占位符），
  而契约 `workboard-contract.md` 写的是"池内真实 key 数"。密钥一个没接上、池实际 0 把、
  请求全 503 时它照样报 `keys: 3`。已改为真实可用数并新增 `unresolved` 字段。
- **URL 拼装约定**：anthropic 的 `base_url` 给 host 根（`BuildURL` 自补 `/v1/messages`），
  openai 给到 `/v1`。配置写错会得到 `POST /v1/v1/messages` → 404。
- **共享 slice 陷阱**（未触发但已设防）：`pv.Keys` 与 `cfg.Providers[i].Keys`、
  `state.FreeProviders()` 共享底层数组，就地清零会静默搞死状态机探测 → 永久卡付费层。
  现只置空副本的 slice header。
