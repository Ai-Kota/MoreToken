## 现场（已查实，非推断）

`/decisions` 的留痕（进程 2026-09-20 14:54 启动）：

```
15:31:48.197  agnes-anthropic 200  auto:reasoning   ← 免费池还在出 200
15:31:49.301  state-machine   all-free-unavailable  ← 1.1 秒后被判"免费全挂"
15:32:08.405  agnes-anthropic 200  auto:reasoning   ← 免费 provider 又出一条 200
15:34:49.565  state-machine   free-healthy>=T       ← 3 分钟后才回摆
```

**判据**：翻档前后免费池都在出 200 ⇒ "这一层挂了"不成立，那次翻档是误判。

**用户可见的错**：15:31:49–15:34:49 之间，`auto:reasoning`（cc-ft 的虚拟模型）**100% 503**。
机制（读代码确定，非推断）：`paidOnly()` 把候选从 3 个删到 1 个，再经 `HasKind(reasoning)`
过滤后**成空集** → 循环一次都不进 → `attempted == 0` → 报
`router: all anthropic candidates cooling (tried 0, limit 4)` → 503。

根因在配置里就写死了：付费档只有 `agnes-paid-anthropic`（`agnes-3.0-flash`，
kinds=`[coding, general]`）—— **兜底档接不了主力工作负载**。

## 定性（用户，2026-09-20）

> **免费池是主力，付费只是暂时应急，不能当做主力来使用。**

由此三条设计约束：

1. **触发**：本请求真的需要 —— 不是"系统进入了某个状态"
2. **作用域**：止于本请求 —— 不粘连到后续请求
3. **持续**：由主力真实状态决定 —— 没有最短占用期

旧实现三条全违：sink 无参数（任何 format/kind 的耗尽 → 全局状态）；
`State.tier` 是粘性的（影响后续所有请求）；最短占用 `HealthyFor=3min` 且不可提前
（`Run` 只在 PAID 时探测）。

## 关键事实：兜底本来就不需要档位

`candidates()` 返回 `free → paid` 的有序链，`Route` 的循环遇不可用候选就
`continue` / `markBackoff` 往后走 —— **"这一次免费挂了就这一次用付费"是原生行为**。

层门控的**唯一净效果**，是把付费从"这一次请求的备选"提升为"接下来三分钟的首选"。
那不是兜底机制，是把应急升格为主力的机制。

防抖本来就有更细粒度的实现：**池级退避**（`coolDur=60s`，per-provider，到期自愈）。
它判错只赔一次尝试，不赔整层能力。

### 改动 2 是独立缺陷，不只服务于本任务

免费候选若都在退避窗口内被 `continue` 跳过，只有付费候选被真的试过 —— 付费一挂，
`attempted == 1`，sink 照样触发：**判"免费耗尽"，而免费层一个请求都没发过**。
`555e60c` 立的规矩（退避不是可用性证据）当时只用在了 `attempted == 0` 那个出口。

### 改动 4 顺带修好一个盲区

旧口径"停在付费档才探全部"下，**整体还在免费档、只有某个池被隔离**时，那个池
只能干等退避到期；吃 401/403 长禁（1h）的更是没有提前解除途径，免费池随时间被慢慢啃掉。
