# T-019: 发布失败指标（网关自述服务质量）

> 起因（用户提议）：**"如果 moretoken 能够把自身的运行状态通过 NATS 发布出来就好了，
> 不需要增加软件；如果出现问题能够调用 agent 进行问题分析和修复。"**

**允许修改文件**：internal/**, main.go, docs/**

## 先查实：第一半已经有了

T-014 修的就是这条链路（它当时断在三处：PATH / 变量名 / CLI 默认 context）。
实测订阅 `aimly.system.freetier.status` —— **每 30s 一份池快照，档位翻转事件也发**。
所以今天那 7 次降级，**事件本身早就广播出去了**，只是没人接。

**真正的缺口在内容**：

| 已发 | 没发 |
|---|---|
| 池快照（keys/cooling/backed_off） | **成功率** |
| 档位翻转事件 | **请求量 / 延迟** |
| | **单条失败** |
| | **按 (format, kind) 的分解** |

⇒ 看板能看到"翻档了"，**看不到"翻了 7 次、坏了 16 个请求"**。

## 第一性原理

### 为什么是"统计"而不是"探测"

网关每次真实请求**本来就知道**成功没成功、落到哪个模型、花了多久——**零成本的事实**。
另起一个进程去探测同一件事，是在烧它本该保护的那份免费配额。

> `model-watchdog` 的前车之鉴：30–45s 探针 × 每模型 ≈ **2000+ req/天/模型**，
> 而 OpenRouter 免费档只有 **50 req/天/模型**。它的评审原文：
> 「per-model 存活探活这个老本行，既被网关吸收、又烧配额、又测不出真正的病。」

⇒ **观察者只许消费事实，不许重新探测。而网关自己就是那个事实源。**

### 为什么"有失败"不是触发判据

网关绝大多数失败是**设计来自愈**的：key 冷却 60s / 池退避 60s / 免费层恢复 ~180s /
dev-fleet 拉进程 300s。

实测（09-21，9.5 小时样本）：**降级 7 次，每次 3.0–8.1 分钟自愈，7 次全是自愈能搞定的。**
按"有失败就调 agent"会被叫 7 次，而每次都是去做一件**已经在被做完的事**。

> **正确判据 = 自愈承诺的超时**："同一现象超过 N × 承诺时间仍未消失"。
> 按这个过一遍那 7 次：**只有 09:11 那次（8.1 分钟）该升级**，其余 6 次不该。

## 实现

### `internal/metrics` —— 滚动窗口（按**时钟分钟**分桶）

为什么按时钟分钟而不是"最近 N 次请求"：判据要能与**时间**比较（自愈承诺是分钟），
按请求数计的窗口换算成时间会随流量漂。

产出两条信号：

| 信号 | 回答 |
|---|---|
| 窗口成功率 / 请求量 / 延迟 / `by_kind` | 最近好不好、是哪一类在坏 |
| **`degraded_sec`** | **当前这轮连续失败持续了多久** ← 升级判据的输入 |

`degraded_sec` 的语义刻意做窄：**一次成功即清零**。它是"这一波坏掉了"的检测器，
不是"历史上坏过"的计数器。

### 接线

- `proxy` 在**每个出口**记一次（405/400/413/503/200/流式）——**不包装 ResponseWriter**，
  那会破坏 `w.(http.Flusher)` 断言、把流式打回缓冲。
- `kindLabel` 归一化：虚拟模型用它的 kind，**字面模型统一记 `literal`**
  ——上游有上百个模型号，放进维度就无限膨胀。
- 并进既有的 `status` payload（**不新开主题**：主题是注册制的，新主题要登记；
  而"我现在的状态"本来就该包含"我最近干得怎么样"）。加字段对既有订阅方安全。

## 触发链路（已落地）

```
网关 /doctor（进程内算——**指标窗口活在跑着的那个进程里**，
              另起进程自己起个窗口永远是空的 ⇒ 一个只会说 ok 的监测器）
   ↓ HTTP
moretoken.exe -doctor      退出码 0 正常 / 1 自愈失效 / 2 网关不可达
   ↓
dev-fleet 的 freetier-doctor（type: cli —— **只报告，不重启**）
   ↓ 心跳
NATS → WorkBoard
```

**退出码分三档是刻意的**：`2`（网关不可达）是**存活**问题，归 `/health` 与 dev-fleet
的重启路径；`1`（自愈失效）才是**升级**。混成一个非零码，就会让升级逻辑去处理它管不了的事
——重启解决不了自愈失效。

**为什么用 `type: cli` 而不是并进 `/health`**：`/health` 是存活探针，dev-fleet 拿它判"要不要重启"。
并进去会变成「降级太久 → 判不健康 → 重启 → 指标窗口清空 → 又健康 → 下次再降级再重启」的重启永动机，
且每次重启都丢掉现场。cli 探针没有可拉起的 bin，只报告。

## 未做（刻意）

**最后一步没有自动拉起 agent**，只做到"升级信号被人看到"。理由写在 runbook §四：
自动 spawn 一个改生产代码的 agent 是风险最高的动作，而目前**没有"agent 改错了"的实战经验**。

它训练人忽略告警（本仓在"假绿训练人忽略闸"上栽过一次）。
