# T-031: 虚拟模型遇「上游 404」就地终止、上游模型名泄漏给客户端（先钉判据）

> 起因：用户真实 cc-ft 会话弹「There's an issue with the selected model (auto:reasoning).
> It may not exist or you may not have access to it. Run /model…」。

**允许修改文件**：internal/proxy/**, internal/router/**, docs/**
**允许新增文件目录**：internal/proxy/, internal/router/, docs/

## 判定（本轮 = 只钉判据 + 留证据，**不改路由行为**）

1. **故障注入测试**（`internal/router/modelrotate_test.go`）：
   - `TestRoute_VirtualModel_LastModel404_MustNotLeak` —— 首选 provider 只有一个 reasoning
     模型、该模型 404、备选 provider 健康时，**当前**就地终止、把 404 透传给调用方。
     对旧代码**为红**（守本仓「【当前为红】」惯例）。
   - `TestRoute_VirtualModel_RecognizedNotFound_FallsThroughToNextProvider` —— **对照实验**：
     同场景、仅把 404 body 换成含 marker 的措辞 ⇒ 变**绿**（沿候选链继续）。两条合起来划出边界。
2. **透传路径留 body**（`internal/proxy/proxy.go` + `decisionbody_test.go`）：
   非 2xx 且无 `Fail.Reason` 时，把上游 body（截断 300B）记进 `/decisions` 的 `Reason`。
   此前这条路径 `reason` 恒空——排查时只能靠推断，正是「吸收即销毁证据」要堵的形态。

## 机制（读码 + **对照实验实测**，非推断）

`tryCandidate`（`router.go:562-568` / `:603-606`）两处对"该 provider 内**没有下一个模型**"
的返回**不同**：

| 上游 404 的归类 | 无下一个模型时的返回 | 后果 |
|---|---|---|
| **FailNone**（body 没被 marker 认出，`:567`） | `done=true` | 404 当**完成态**上抛 ⇒ proxy 原样透传（`proxy.go:388-390`）⇒ **泄漏** |
| **FailModelNotFound**（body 被 marker 认出，`:606`） | `done=false` | Route **继续沿候选链**到下一个 provider ⇒ 不泄漏 |

**精确成因**：`isModelNotFound` 的 marker 全为 OpenAI 味措辞（`does not exist` / `unknown model`
/ `model not found` …，`provider.go:137-144`），**不含 Anthropic 规范的 `not_found_error` 形状**。
于是上游那道规范 404 归 `FailNone` ⇒ 就地终止 ⇒ 客户端按**自己配置的模型名**（`auto:reasoning`）
渲染成"模型不存在"。

> 边界澄清（曾一度写反，靠对照实验纠正）：
> ① 有下一个模型时，**任何** 404 都轮换（判据看状态码，与 body 无关）；
> ② **走到最后一个模型时**，是否终止取决于 marker 能否认出 body。**缺陷出在 ②。**

## 判据来源

- `/decisions`（400 条）：`auto:reasoning` 3 条 `provider=xkiro-anthropic status=404
  model=minimax/minimax-m3:free`，`retried=true`，`elapsed_ms` 102–115s。
- `config/models.auto.json`（2026-10-05 生成）：xkiro 已无 `minimax/minimax-m3:free`（退役）。
- `config/config.json` 手写区：`xkiro-anthropic` 的 reasoning 模型**仅** m3 一个。
- 对照实验：`modelrotate_test.go` 两条（红/绿）——本缺陷的**最小复现**。

## 本轮不做（留 T-032）

- **判据 I3**：`isModelNotFound` 识别 Anthropic 规范 `not_found_error`（须按 **JSON 结构**识别，
  不得裸匹配 `model: ` 子串——见 `provider.go:134-136`「宁可窄」纪律）。这是本缺陷的**直接修法**。
- **供给冗余**：让 `auto:reasoning` 在 anthropic 路上有 ≥2 个活的可用模型（纵深防御）。
- **模型级 de-admission**：让已退役模型出池（否则每次仍撞一次 ~100s 的 404）。
