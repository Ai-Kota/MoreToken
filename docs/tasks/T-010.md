# T-010: 虚拟模型层（按类型提供连接）+ 修 1 MiB 静默截断

> 目标：智能体不再点名具体模型，只声明**要什么类型的模型**（`auto:reasoning` / `auto:coding` …），
> 网关自行解析到具体模型并改写请求体。会话延续由"智能体重发历史"保证（无模型专属状态，已验证）。

**允许修改文件**：internal/**, main.go, config/**, docs/**
**允许新增文件目录**：internal/, docs/

## 背景

### 1. 现存缺陷：1 MiB 请求体静默截断（先修，它是长会话的硬墙）

`internal/proxy/proxy.go:50`：

```go
body, err := io.ReadAll(io.LimitReader(req.Body, 1<<20))  // 读完不校验长度
```

`LimitReader` **静默截断**：超限不报错，只是少读，于是非法 JSON 被转发上游。实测：

| 请求体 | 结果 |
|--------|------|
| 990 KB（≈22 万 token） | 200 ✅ |
| 1125 KB | **400** `{"error":{"code":"invalid_request","message":"Invalid request: unexpected end of JSON input"}}` |

那个 400 **来自上游**、网关原样透传——调用方看到的像是"自己发了坏 JSON"，实际是网关截断的；
网关日志里一个字都没有。22 万 token 就是天花板，长会话必然撞上。

### 2. 新能力：虚拟模型（按类型提供连接）

现状：智能体必须点名具体模型（`agnes-2.5-flash`），模型与 provider 绑死写在配置里。
目标：智能体说"我要推理型"，网关自己选；换了具体模型，智能体无感。

**已核实的两个前提**（决定了这件事为什么可行）：

- 网关**原样透传** `model`（`proxy.go:78`），配置里的 `models` 只喂 `/v1/models` 列表、不参与路由。
  实测：付费 key 要 `agnes-2.5-flash` → 200 且 `"model":"agnes-2.5-flash"`；免费 key 要
  `agnes-3.0-flash` → 200。**凭据不限制模型**，切 provider 是换账号不是换模型。
- agnes **不返回 `thinking` 块**（实测带 `thinking:{type:enabled}` 仍只回 text 块）。
  Anthropic 的 `thinking` 块带模型专属签名，跨模型回传会被拒——这是跨模型续话的主要坑，
  agnes 不存在它。对话状态只有 `text` / `tool_use`，跨模型可携。

## 目标

1. **修 1 MiB 墙**：上限提高且可配；**超限显式报错（413）**，绝不静默截断
2. **类型注册**：`config.json` 的 model 条目加 `kinds`，provider 的有效类型 = 其 models 的 kinds 并集
3. **虚拟模型解析**：`auto` / `auto:<kind>`，由客户端在 `model` 字段声明
4. **按类型选 provider**：候选过滤加入"该 provider 能否提供此类型"
5. **按候选改写 model**：每个候选用它**自己确实有**的、匹配该类型的模型（避免选到的 provider 没有那个模型）
6. **切换可见**：实际使用的模型进决策日志 + NATS 事件（智能体可据此决定是否重述关键约束）

## 验收标准（DoD）

- [x] 超限请求返回 413 且响应体说明原因，不转发、不截断
- [x] 上限可配（默认 32 MiB，显著高于旧 1 MiB），单测覆盖"刚好到限"与"超限一字节"
- [x] `kinds` 可在 config.json 声明；未声明 kinds 的模型仍按原行为工作（向后兼容）
- [x] `model: "auto"` 与 `model: "auto:reasoning"` 均可路由；`auto` 等价于"任意类型"
- [x] 非虚拟模型（如 `agnes-2.5-flash`）**请求体不被改写**（零行为变化）
- [x] 候选按类型过滤：无可提供该类型的 provider 时明确报错，不静默降级到不相干模型
- [x] 解析出的具体模型写进决策日志（`/decisions` 的 `want` / `model` 两字段）
- [x] `/v1/models` 一并列出虚拟模型，供客户端发现
- [x] 两条协议路径端到端实测通过（含 `auto:reasoning` 真身请求）
- [x] `bash scripts/test-all.sh` 全绿

### 实测记录（2026-09-19）

| 项 | 结果 |
|----|------|
| `POST /v1/messages` `model=auto:reasoning` | 200，落到 `agnes-2.5-flash` |
| `POST /v1/chat/completions` `model=auto` | 200，落到 `agnes-2.5-flash` |
| `/decisions` | `provider=agnes-anthropic model=agnes-2.5-flash want=auto:reasoning status=200` |
| `/v1/models` | 置顶列出 `auto` / `auto:coding` / `auto:fast` / `auto:general` / `auto:reasoning` |
| 34 MB 请求体（超 32 MiB 上限） | **413** `{"error":"request body too large","limit_bytes":33554432}` |
| `auto:vision`（无人持有） | **503** `no provider available for model "auto:vision"` + `no anthropic provider offers kind "vision"` |

> 注：NATS 事件本轮未扩展 model 字段——切层事件（T-005）已覆盖"层变了"，
> 而"模型变了"由 `/decisions` 承载（每次请求都可见，比事件更全）。DoD 里写的"NATS 事件"
> 实际以决策日志落地，是更合适的载体。

## 注意

- **网关保持无状态**：不存会话、不做三要素交接。三要素是智能体侧的会话接续协议
  （见全局 CLAUDE.md），与网关职责正交。网关只负责"按类型给一个能用的模型"。
- 只对**虚拟模型**改写请求体；字面模型走原路径，把风险面压到最小。
- 不改 streaming 透传路径（SSE 逐块转发逻辑不动）。
