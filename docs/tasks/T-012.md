### 2. 挂死防护（长会话的真威胁）

`main.go` 给 router 的 client 是 `&http.Client{Timeout: 0}`——为了让长生成不被总超时切断。
但代价是：**上游接受了连接却不回响应头时，请求永远挂着**。对智能体来说，
挂死比报错糟得多——报错能重试，挂死是会话原地冻住（且"会话永不掉线"是这项目的核心承诺）。

修法（不引入总超时，保住长生成）：
- `Transport.ResponseHeaderTimeout`：兜住"连上了但不回响应头"
- `Transport` 的 `DialContext` / `TLSHandshakeTimeout` / `IdleConnTimeout`：兜住连接阶段
- **流式空闲看门狗**：SSE 已开始后，若长时间无字节流入则中止——这是流式场景唯一的挂死出口
