# T-050: 运行记录（给智能体做优化证据的 JSONL 遥测）

> 状态：**✅ 完成并部署验证（2026-10-25 15:57，mt-deploy 15 PASS / 0 FAIL）**
> 用户定性：需要的是一份**完整的运行记录**，给智能体分析、优化、完善网关；
> 不需要人每天盯看板，也**不引入** Prometheus/Grafana/告警新栈。

## 目标

在网关内落一份**宿主可读、按天轮转**的 JSONL：

- `type=request`：每个 `/v1/messages` / `/v1/chat/completions` 请求一行。
- `type=snapshot`：每 60 秒一行池/tier/指标/admission/配置版本快照。
- `type=boot` / `type=shutdown`：进程边界。

不记录：key 明文、请求/响应正文、prompt。key 只记池内 ID（`provider/keyN`）。

## 字段（request）

`ts, request_id, boot_id, client, protocol, stream, want, virtual, want_kind,
provider, model, status, outcome, fail_reason, total_ms, ttft_ms,
req_bytes, resp_bytes, input_tokens, output_tokens, usage_known,
budget_raised, config_hash, admission_mtime, admission_size,
attempts[]`（每次 key 尝试：provider/model/key_id/kind/status/reason/elapsed_ms/stream）

## 关键实现点

1. 新包 `internal/telemetry`：按天轮转的 JSONL writer、保留天数清理、nil 安全、异步/低开销。
2. `router.Attempt` 增加 `key_id`；`RouteRequest` 增加 `AttemptSink`，**成功路径也逐 key 留痕**。
3. proxy 在请求出口统一写一条记录；客户端取消单独分类为 `client_canceled`（不再混进 503 失败）。
4. 流式首块记 TTFT；非流式 TTFT=总耗时；token 从响应 JSON/stream chunk 尽力提取。
5. `config_hash` 只哈希策略面（provider/base/model/kinds/排除名单等），**不含 key**；
   `admission_mtime/size` 标识准入表版本。
6. compose 增加 rw 挂载 `./runtime/telemetry:/var/lib/moretoken/telemetry` 与 env。
7. `scripts/mt-report.py`：按天/模型/provider/客户端/失败类型/延迟分位出摘要，支持 `--json`。
