# T-044: 虚拟模型输出预算下限——推理型请求不再被小 max_tokens 测成残废

> 来源（T-041 追加二，有数据）：免费主力 agnes-2.5-flash 是**推理型**，思考链
> 极长。客户端默认给 32–128 的 max_tokens ⇒ 思考吃光预算、**正文 content 恒空**
> （finish_reason=length）⇒ 难题 8 题里 7 题"答不出"。预算给到 4096 后同题
> 6/8 对——**同一模型，纯预算差异**。任何调用方（Claude Code 的短答场景、
> 脚本、其他工具）默认小预算，都会把这个现象重演一遍。

**判据（T-041 追加二实测）**：`E:\tmp\mt-ab\cmp-free4096.json`（4096 预算，
出 64–853 token 即正常作答）vs `cmp-answers.json`（32–128 预算，content 全空）。

## 交付

1. `config.Config.MinOutputTokens *int`（指针语义沿用 T-040/T-042 先例）：
   - 未配置 = **缺省 4096**（数据支撑：4096 是今日实测的"够用"线）；
   - 显式 0 = 关（完全尊重客户端原值，回归闸）；
   - 显式 N = 自定义下限。
2. 语义（**只抬不降**）：
   - 仅对**虚拟模型**（auto / auto:*）生效——"网关替你挑的池"才由网关兜底；
     字面模型（基建工具点名）一个字节不动（与 admission 过滤同款纪律）。
   - 改写规则：请求体 `max_tokens` 缺失或 < 下限 ⇒ 抬到 `min(下限, 该模型
     已声明的 max_output_tokens)`（有模型上限声明时封顶，不造出超限请求）；
     客户端已给更大值 ⇒ 原样（不降）。
   - anthropic 格式同样适用（其 `max_tokens` 为必填，缺省时按 4096 补上
     而非报错——与代理定位一致：网关替调用方兜住默认值）。
3. 可见性：抬预算时在该请求的 /decisions reason 标 `budget_raised <old>→<new>`
   （不静默：改过请求体必须是可审计事件，T-020 同款纪律）。
4. 测试：
   - 虚拟模型 max_tokens=64 ⇒ 被抬到 4096（有 4096 上限声明的模型封顶）；
   - max_tokens=8192 ⇒ 原样；无 max_tokens 字段（openai）⇒ 补 4096；
   - 字面模型 64 ⇒ 原样（回归闸）；
   - MinOutputTokens=0 ⇒ 全不动（回归闸）；
   - 变异检验：抬预算逻辑摘除 ⇒ 红。

## 判据
- `go test ./...` 全绿；宿主起网关实打一发 `auto:reasoning` + max_tokens=64
  ⇒ /decisions 出现 `budget_raised 64→4096`，且本次请求正文非空（难题 4 题
  复验中至少 Q4/Q5 出终答——用 T-041 追加二的同题，不烧付费）。

**允许修改文件**：internal/config/config.go, internal/router/router.go, internal/router/router_test.go, internal/proxy/proxy.go, docs/**
**允许新增文件目录**：无

## 不做
- 客户端侧（Claude Code 的 ANTHROPIC 默认参数）不改——那是调用方的事；
  网关只做"托底下限"，不替它决定上限。
- 流式请求的 max_tokens 语义同非流式，同一改写点（SetModel 后），不做特殊路径。
