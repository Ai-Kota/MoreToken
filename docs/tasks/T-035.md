# T-035: 403 按账号（key）而非模型处理 —— "不能循环找活模型"的根

> 2026-10-05 部署后实测发现：xkiro 对**同一个模型**，部分 key 200、部分 **403 `denied`**；
> 而 moretoken 依 2026-09-20 的结论把 403 当**模型级**（只换模型、**不换 key**）⇒
> 抽到无权限的 key 就只能换模型（同样无权限）⇒ 耗尽 ⇒ 503。实测约**五成**。

**允许修改文件**：internal/router/**, internal/pool/**, docs/**
**允许新增文件目录**：docs/

## 第一步（**必须先做**）：受控实验

分辨"**同一模型换 key 是否可能 200**"——这决定 403 到底是不是 key 级事实。

- 取一个上游模型（xkiro `qwen/qwen3-max:free`），逐把 key 直打 `api.xkiro.com`（容器内，绕开本机 TLS）。
- **200 与 403 并存** ⇒ key 级事实，改法成立。
- **全 403** ⇒ 模型级事实，2026-09-20 的结论对，**本任务应作废**。
- 全 429 ⇒ 平台当日额度用尽，**实验被阻断**，改日重做。

## 第二步（实验通过才做）：改法

`tryCandidate` 的 key 循环里，`FailDenied` 目前落到 `:603`（换模型）。
改为：**换 key 再试一次**，但——

- **不** `RecordDead`（保住 2026-09-20 的成果：403 不惩罚 key）；
- 需 pool 支持"**换一把与刚才不同的 key**"（现在 `Select()` 可能返回同一把）。
- 全部 key 都 403 ⇒ 才落到模型级/provider 级（与今天一致）。
