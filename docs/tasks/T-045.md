# T-045: 容器形态启用 admission 表挂载（T-039 容器跟进）

> 前置：T-039 在**宿主形态**接了 `admission_path`，但容器里 `E:\` 盘不可见
>（docker-compose.vault.yml 注释已备好挂载三步，源文件一直缺）。生产容器跑的是
> 旧镜像 + `admission.active=false`（今日 /doctor 实测）。本任务把准入表真正上生产。

**来源**：2026-10-08 部署前体检发现生产容器 13h 未动、T-039/040/042/044 均未上生产；
`/doctor admission={active:false, models:0}` 坐实容器里准入表没接。

## 交付（T-039 既定三步，见 compose 注释 44-64）

1. 拷产物到宿主：`cp TEST/model-evaluator/admitted.json → docker/runtime/admitted.json`
2. compose 解开挂载注释：`- ./runtime/admitted.json:/run/admission/admitted.json:ro`
3. `config/config.json` 的 `admission_path` 由宿主 `E:\` 绝对路径改为容器内
   `/run/admission/admitted.json`（容器里宿主路径不存在；改容器路径后宿主形态
   启动会读不到该文件 → admission fail-open 回退 kinds，不炸——两形态取舍见下）

## 判据
- `bash docker/mt-deploy.sh` 全 PASS（含 mt-verify 全量矩阵）；
- 容器起后 `curl :8462/doctor -H token` 里 **`admission.active == true`**（唯一真判据，
  compose 注释明写"别看脚本报成功，看这个"）；
- `min_ratio == 0.8`。

## 取舍（诚实标注）
- 改 `admission_path` 为容器路径后，**纯宿主形态**（不跑容器、直接 `moretoken.exe`
  起）会读不到 `/run/admission/...` ⇒ admission fail-open。宿主形态若也要 admission，
  需另指宿主路径——两形态各取所需，不混在一个 admission_path 里。
- 热加载已接线（admission.Table.Watch 30s mtime 轮询）⇒ 日后表更新**不必重启容器**，
  拷新 admitted.json 到 runtime/ 即可。
