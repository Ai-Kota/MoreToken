# T-022: 上下文超限的快速失败 + 上游原文留痕

> 起因：用户报「又一个会话卡的时间很长」。

**允许修改文件**：internal/**, main.go, docs/**

## 现场（2026-09-22 13:11–13:18）

```
agnes-anthropic  upstream  el=68741  status 502  body=2514KB
xkiro-anthropic  upstream  el=3716   status 0    model rotation exhausted
```

**6 条 503 的 body 全是 2514KB，一模一样** —— 同一个会话在反复重发同一个请求。
每个候选先扛 60–80 秒，试完再给 503，客户端重试……看起来就是"卡了很久"，而且**会永远卡下去**。

## 根因（上游自己的原话）

直连 agnes 拿到：

```json
"ContextWindowExceededError: The input (994166 tokens) is longer than
 the model's context length (524288 tokens)."
```

**会话上下文 99.4 万 token，模型上限 52.4 万——近 2 倍。**

## 两个网关侧的真问题

### ① 我们把上游原文丢了

留痕里只有 `status 502`，而 agnes 真正想说的是"上下文超限"。
本仓排查手册原话：「**上游返回的原文要留下来，它直接指出方向；顺手改写成'上游不可用'就把线索丢了**」
——`FailUpstream` 的 reason 曾经就只写状态码。

**修**：`FailUpstream` 的 reason 带上游原文（截断 200 字节）。

### ② 确定性失败不该重试

上下文超限对**所有候选、所有 key**都是同一个答案——重试只是让调用方白等，
最后仍是一个注定的失败。而且 503 会**诱导智能体重试**。

**修**：
- 新增 `provider.FailContextTooLong`（**不可重试**）
- 判据**看 body 不看状态码**——同一件事 agnes 直连回 400、经它的网关回 502
- `router.ErrContextTooLong` 哨兵 → proxy 映射成 **413 + 可操作提示**

| | 改前 | 改后 |
|---|---|---|
| 上游调用次数 | 2–3 个候选各一次 | **1 次** |
| 耗时 | 60–80 秒 × N | **12.4s** |
| 调用方看到 | `503 all providers exhausted`（诱导重试） | **`413 context window exceeded`** + 原始 token 数 + "压缩会话或开新会话" |

## 验收（DoD）

- [x] `isContextTooLong` 认得上游真实原文 + 常见变体；**无关错误不误判**（误判 = 本该重试的变成确定性失败）
- [x] `FailUpstream` 带原文（单测断言 reason 含上游文本）
- [x] `FailContextTooLong` 不可重试 + 稳定短名 `context_too_long`
- [x] 路由**只打一次上游**（单测断言 hits==1）+ 返回哨兵错误
- [x] proxy → 413 + hint + **进决策日志**（这条也是"没有响应"的失败，不记现场又是空白）
- [x] `bash scripts/test-all.sh` 全绿
- [x] **真身复现**：2.5MB 请求 → HTTP 413 / **12.4s**（改前是 60–80 秒起步 + 503）

## 未做

**网关无法替调用方压缩上下文**——这是智能体的会话管理问题。网关能做的是
"**快速、明确地告诉它**"，这一轮做完了。

## 顺带

被判"卡住"的那个会话**需要压缩或重开**才能恢复：99.4 万 token 已是上限的近 2 倍，
它自己不会好。
