# T-013: 修 check-scope 的意图门禁死锁（TASKS.md 不豁免）

> 缺口：`isTaskDefinitionPath` 只豁免 `docs/tasks/T-*.md`（要求 basename 以 `T-` 开头），
> 而 `begin-task` 又要求任务行已存在于 `docs/tasks/TASKS.md`。于是——
> **登记新任务需要已声明的任务**，死循环。
>
> 本轮（T-009 建任务时）撞过一次，靠"先设 tracker 的 task_id 再正规 begin-task"绕过。
> 那是绕，不是修。

**允许修改文件**：scripts/**, ../jiutian/scripts/**, ../../SPT/scripts/**, ../../TEST/GoStrix/scripts/**, ../../TEST/model-evaluator/scripts/**, docs/**
**允许新增文件目录**：docs/

## 缺口成因

`scripts/cmd/ai-guard/check_scope.go`：

```go
func isTaskDefinitionPath(p string) bool {
	base := filepath.Base(p)
	return strings.HasPrefix(p, "docs/tasks/") && strings.HasSuffix(p, ".md") &&
		strings.HasPrefix(base, "T-")   // ← "TASKS.md" 不以 "T-" 开头
}
```

而同文件 `isBlockedPath` 上方的注释把意图写得很明白：

> *the intent gate must not block creating/maintaining **the very task files that unlock it***

`TASKS.md` **正是**解锁门禁的那个文件（`begin-task` 读它的任务行）——实现漏了它。

且 `check-bash-write` 复用同一个 `enforceWriteScope`，所以 shell 绕（`echo >`、`sed -i`）同样被拦，无旁路。

## 修法

```go
// isTaskDefinitionPath reports whether p is a per-task definition file
// (docs/tasks/T-*.md) or the task board index (docs/tasks/TASKS.md).
//
// TASKS.md 列入其中：begin-task 靠它的任务行校验任务 ID，缺它则门禁死锁。
// 本改动只放宽"无任务"窗口——任务一旦声明，isBlockedPath 即不可达，
// TASKS.md 照常受任务边界（loadTaskBoundaries/isAllowed）约束。
func isTaskDefinitionPath(p string) bool {
	base := filepath.Base(p)
	return strings.HasPrefix(p, "docs/tasks/") && strings.HasSuffix(p, ".md") &&
		(strings.HasPrefix(base, "T-") || base == "TASKS.md")
}
```

**安全性论证**：`isTaskDefinitionPath` 只在 `isBlockedPath()` 里被调用，而 `isBlockedPath()`
**只在"尚未声明任务"时**才可达（`check_scope.go` 的 `if taskID == "" || !fileExists(...)` 分支）。
所以：

- 无任务时：`TASKS.md` 可写 → 能登记任务 → `begin-task` 走通 → 死锁解开
- 有任务后：走 `loadTaskBoundaries` + `isAllowed`，`TASKS.md` **照常受任务边界约束**，不会变成永久可写

### 途中修正的两处我自己的错

1. **测试断言写反了**：把 `if isBlockedPath(x) { t.Error }` 写成了"返回 true 就报错"，
   而 true 恰恰是"被拦"的正确行为。测试当场抓住——这正是写它的意义。
2. **构建失败于 go.work**：4 份副本直接 `bash build.sh` 报
   `cmd\ai-guard is contained in a module that is not one of the workspace modules listed in go.work`
   ——根 `go.work` 没列它们的 `scripts` 模块（本仓有自己的 `go.work` 所以没撞上）。
   用 `GOWORK=off` 让各模块独立构建解决，**不动根 go.work**（那会波及其它会话）。
