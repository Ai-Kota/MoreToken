## 结论（已核实）

**xkiro 是活的，免费档有活模型。真正死掉的只有 minimax 一族。**

| 事实 | 证据（容器内 / 网关实测，正确 token） |
|---|---|
| xkiro 可达，目录 129 个模型 | `GET https://api.xkiro.com/v1/models` → 200 |
| 目录用 `id` + `access_tier`(paid/premium/free) 表达档位 | `minimax/minimax-m3` 现为 `access_tier=paid` |
| xkiro 免费档**能服务** | `qwen/qwen3-max:free`、`qwen-plus-2025-07-28:free`、`qwen3-coder-plus:free` 实测 **200** |
| **minimax 整族已从目录消失** | 纳新 verified 的 25 个里，消失的 6 个**全是** `minimax/minimax-m*:free` |
| 手写 `minimax/minimax-m3:free` 已不在目录 | 目录里只有裸 `minimax/minimax-m3`（tier=paid） |

## 为什么只有 `auto:reasoning` 没有兜底（回答用户）

各模式在 `xkiro-anthropic` 上的兜底模型：

| 模式 | 兜底模型（该 provider 持有此 kind 的） | 活? |
|---|---|---|
| `auto:coding` | `qwen/qwen3-coder-plus:free` [coding] | ✅ 200 |
| `auto:general` | 一批 qwen [general] | ✅ |
| `auto`（任意） | 同上 | ✅ |
| **`auto:reasoning`** | **`minimax/minimax-m3:free` [reasoning]** | ❌ 已下架 |

`auto:reasoning` 在 xkiro-anthropic 上**唯一**持 reasoning 的模型就是那个已下架的 minimax
⇒ 候选过滤后**没得换** ⇒ agnes 一挂就 503。**cc-ft 恰好用的就是这唯一没有活兜底的模式。**

## 结构性诱因（代码层，非本任务修复）

1. `MergeAuto`（`config/auto.go`）**只追加、永不删**——上游下架的 id 永久留在 config。
2. 纳新 `Run`（`catalog.go`）用 `Known` **跳过**已在 config 的 id ⇒ 已失效的旧 id **永远不会被重新实测**，
   也就永远不会被发现"已死"。
3. 于是死 id 不仅驻留，还占据**偏好首位**（先于后纳进来的活模型）。

## 修法选项（待用户定，另立任务）

- **A 立刻解锁**：cc-ft 的 `ANTHROPIC_MODEL` 从 `auto:reasoning` 改为 `auto`（任意）——
  立刻获得 xkiro 的活兜底。代价：放弃"要推理型"的语义。
- **B 补回 reasoning 供给**：给 `xkiro-anthropic`（及 `xkiro`）填一个**实测可用**的 reasoning 模型
  （候选 `qwen/qwen3-max:free`，实测 200），替换已死的 minimax。触碰 `config/config.json`（生产）。
- **C 治根**：让纳新能**淘汰**已下架 id（`MergeAuto` 支持剪枝 / 依据目录差集标记失效）。
