## 改动（一处，最小面）

`internal/provider/provider.go` 的 `isModelNotFound`：在既有 OpenAI 味 marker 之外，
**按 JSON 结构**识别 Anthropic 规范形状：

```json
{"type":"error","error":{"type":"not_found_error","message":"model: <id>"}}
```

**纪律**（用户定过，`provider.go:134-136`）：因误判代价不对称（把"上游故障"误判成"模型不存在"
会让本该重试的失败变成终局），判据**宁窄勿宽**。故：

- 认的是**结构化字段** `error.type == "not_found_error"`，**不是**子串；
- **不**裸匹配 `model: ` 子串（会误伤无关错误体）；
- **不**加 `message` 措辞约束——那等于退回"依赖上游写法"；且在 `/v1/messages` 上
  `not_found_error` 本就是模型级的**确定性**答复（不是瞬态故障），无需再收窄。

## 期望效果（一条链）

xkiro-anthropic 对已退役 `minimax/minimax-m3:free` 回的规范 404
→ 归 `FailModelNotFound`（原为 `FailNone`）
→ `tryCandidate` 在「该 provider 内无下一个模型」处返回 `done=false`（`router.go:606`）

→ 全部耗尽则落 **503**（网关侧失败），**不再**把 404 甩给客户端。
