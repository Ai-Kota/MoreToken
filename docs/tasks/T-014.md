# T-014: 修 NATS 发布链路（监控前端的数据源从未通过）

> 起因：查"有没有前端监控界面"时发现——**前端有，但它的数据源一直是断的**。

**允许修改文件**：internal/**, main.go, docs/**, ../../ops/dev-fleet/services.yaml
**允许新增文件目录**：internal/, docs/

## 现状（已查实，非推断）

**前端存在**：`E:/repos/aimly-console/src/modules/freetier/MoreTokenModule.jsx`（6.7KB，9/13），
已在 `_registry.js` 注册。订阅 `aimly.system.freetier.status` / `.event`，渲染当前层、
池状态表、事件时间线，并有"90s 无 status → 标总线离线"的检测——与契约对得上。
（我此前说 T-008"未实现"是**错的**，此处更正。）

**数据源是断的**，三层叠加：

1. **PATH**：`nats.exe` 在 `E:/AImlyForge/tools/bin/`，不在服务进程 PATH 里
   → `exec.LookPath("nats")` 失败 → `NewPublisher` 直接退化成 no-op。
2. **变量名不匹配**：即便 PATH 修好，网关继承的是 AImlyForge 约定的
   `NATS_SERVERS` / `NATS_USER_CREDS` / `NATS_CA_FILE`，而 **stock nats CLI 认的是
   `NATS_URL` / `NATS_CREDS` / `NATS_CA`**（实测 `nats pub --help`）。
   于是 CLI 回落到它自己的默认 context。
3. **context 指错**：`~/.config/nats/context/AImlyForge.json` 的 url 是
   `nats://127.0.0.1:4222`（**本机**，不是云），且无凭据 → TLS/连接失败。

**外加最致命的一条**：`Publisher.Publish` 的返回值**被调用方忽略**
（`main.go` 里 `pub.Publish(...)` 裸调）→ 三层全挂也**一声不吭**。

实测对照：

| 调用方式 | 结果 |
|---|---|
| 继承三件套 env（网关现状） | `nats: error: tls error: certificate signed by unknown authority` |
| 干净 env（只用默认 context） | 同上（context 指向本机 127.0.0.1） |
| `--server <云> --creds <file>` | **Published** ✅ |
| `NATS_URL` + `NATS_CREDS` env | **Published** ✅ |

## 目标

1. **网关按 AImlyForge 约定读三件套，翻译成 nats CLI 认的 flag**
   —— 连接指南明写"连接 = 环境变量三件套（唯一方式）"且禁止"一服务一形态"，
   所以**不改部署侧造第二套约定**，改网关自己适配。
2. **找得到 CLI**：`nats` 不在 PATH 时，回落到已知路径（沿用 vault 的 `VAULT_BIN` 同款做法，
   加 `NATS_BIN` 覆盖 + 默认 `E:\AImlyForge\tools\bin\nats.exe`）。
3. **失败不再静默**：Publish 失败要留痕（首次/变化时记一条），
   否则"界面永远离线"这种状态无从诊断——这正是本任务存在的原因。
