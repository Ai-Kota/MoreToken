# ADR-004: 健康分层与冷却池 —— 快慢判据分离 + 平台/模型双粒度 + 能力准入

## 状态

**已接受**（2026-10-01 评审通过，5 项待定已定，见文末「已定」）· 补充 ADR-003 的"免费优先"分层，不改变其定位

## 日期

2026-10-01

## 上下文

### 触发：一次真实故障被误读成"模型能力不行"

2026-09-30/10-01 排查中发现，本网关对"模型是否可用"的判断存在**粒度错配与判据混淆**，
且已实际造成误判。三条实测证据：

1. **供给塌缩未被发现**
   - `xkiro` 提供商在配置里声明了 22 个模型。经网关调用 `qwen/qwen3-max:free` 等，**一律 404**
     （`not_found_error`），于是 `auto` / `auto:reasoning` / `auto:coding` / `auto:fast` / `auto:general`
     **五个虚拟模型全部解析到同一个 `agnes-2.5-flash`** —— 虚拟模型这层抽象事实上空转。
   - 但**直打上游 `api.xkiro.com`**：同一把 key × 4 个不同模型（qwen 系 + minimax 系）**全部 200**。
   - ⇒ 不是上游没供给，是**网关没把请求交给它**。根因是 `Route` 对**字面模型**的短路语义：
     "首个候选 provider 说不认识该模型即终止"，而本部署里 agnes 与 xkiro 的模型集**不相交**
     （`qwen/*` 只有 xkiro 有），agnes 排在前 ⇒ **11 把 xkiro key 全成摆设**。

2. **"能力结论"实际混进了"网关缺陷"**
   - 曾有一次外部评估把源清单指向了**网关自身**（`127.0.0.1:8462`）而非上游，
     跑出的准入选表是 **44/44 全部 `anthropic_ok=false`**（原因全是 404）。
   - 那个结论**测的是网关的路由缺陷，被读成了模型的能力不足** —— 判据自噬的活样本。
     ⇒ 由此定下一条**对任何外部测量都适用**的规矩：
     **被测量的流量必须直打被测对象本身，不经被测系统中转**（否则测的是系统、结论写给模型）。

3. **能力标签从未经过实测**
   - `internal/catalog/catalog.go:169-171` 自述：
     > 通过者**只标 general**：实测能证明的只有"它活着并能回一条响应"，证明不了"它会推理"。
     > kinds 是能力断言，**必须人工实测后再升格**。
   - ⇒ 驱动 `auto:*` 选型的 `kinds` 标签是**人工写上去的**，本网关**没有任何能力测量能力**。

### 结构性约束：两类平台的性质不同

| | 单体厂商（如 `agnes`） | 聚合商（如 `xkiro`） |
|---|---|---|
| 模型集 | 自家一族（`agnes-*`，**ID 无 `owner/` 前缀**） | 跨多供应商（`qwen/*`、`minimax/*`，**ID 带前缀**） |
| 故障相关性 | **高** —— 平台一挂全挂 | **低** —— 上游撤单个模型，其余照常 |
| 模型存续 | 自家换代才消失 | 上游**随时可撤**（见 `tryCandidate` 注释："上游悄悄不再提供某个模型（404）是常态"） |

实测印证：`agnes` 侧 33 把 key × 3 个模型 **9/9 全 200**（平台整体健康）；
`xkiro` 侧 22 个模型**大量不可达**（逐个失败）。**两者需要不同的冷却粒度。**

### 现状：池只有 key 级

`internal/pool/pool.go`：`cooldown map[string]bench`（**keyID → 禁用记录**）。
模型级只存在于**单次请求内**（"换同 provider 的下一个模型"），**不落状态、不跨请求**。
⇒ "某模型额度耗尽 → 移出 → 冷却 → 恢复回池" 这套**目前不存在**。

## 决策

### 一、判据分两层，快慢分离（禁止用快判据代替慢事实）

| 层 | 覆盖 | 判据 | 周期 |
|---|---|---|---|
| **快层** | ①额度耗尽（429 / quota / rate_limit）<br>②不可达（404 / 5xx / 连接失败 / 超时） | 响应码与错误分类（确定性信号） | 请求时即时 + 秒级探测 |
| **慢层** | ③**能力降级**（"模型变笨了"） | **agnes-6 题组实测** | 周期（小时/天级），不可快 |

**铁律：快层判据不得用于推断能力。** "它答不上来" 与 "它不够聪明" 是两件事。
前者可即时处置，后者必须由题组说话 —— 否则重演"代理量冒充真值"。

### 二、冷却粒度按 `PlatformKind` 分层

新增 provider 字段：

```go
// PlatformKind 平台性质 —— 决定健康/冷却的粒度
//   vendor     单体厂商（agnes）：自家一族、故障高相关 ⇒ 冷却按 provider/key 级
//   aggregator 聚合商（xkiro）：挂多家、单模型可独立撤换 ⇒ 冷却必须按模型级
PlatformKind string `json:"platform_kind"` // vendor | aggregator
```

- **`vendor`**：平台整体不可用时，**冷却整个 provider**，不得逐模型判死。
  ❌ 反例：33 把 agnes key 被逐个冷却 → 平台恢复后 key 仍在冷却 = **假死**
- **`aggregator`**：**必须逐模型**记录健康与冷却。
  ❌ 反例：一个死模型让整池看起来不可用 = **假死**（正是 2026-09-30 的现场）

**自动推断（已定）**：模型 ID 含 `owner/name` 形态（`qwen/`、`minimax/`）⇒ `aggregator`；
不含前缀（`agnes-2.5-flash`）⇒ `vendor`。
**按 provider 内模型的多数形态判定**（一个 provider 下混有两种形态时，以多数为准并告警），
不手写 —— 避免"新增 provider 忘配字段"这一必然发生的漏配。

### 三、两个桶必须分开：`不可达` ≠ `能力不够`

- **不可达**（快层②）：处置是"冷却 + 换供给"，**结论不得进入能力记录**
- **能力不够**（慢层③）：处置是"移出准入池"，**与网络无关**
- 混桶的代价：拿网关的锅判模型的死刑（本次 44/44 的误判即由此而来）

### 四、能力准入：通过者入池，未通过者不入池；**可逆**

- 驱动方式（已定）：**首次准入 + 按需重测**（不做周期常跑）——能力变化慢，周期性重测的边际价值低，
  而每次重测都要烧免费额度。何时重测由**快层信号**触发（如某模型连续不可达后恢复、或上游换了模型名）
- 首轮：对**全部免费模型**跑 agnes-6 题组
- **通过 → 留池；未通过 → 不入池**
- **`未测` 的处置（已定，严格）：不入池。**
  即"没测过"与"没通过"在准入上同效 —— 宁可少一个模型，不可让没依据的模型冒充合格。
  ⚠️ 代价：首次准入跑完前，池是空的（或只剩已测过的），需接受这段空窗
- 结论必须**带时间戳 + 重测路径**（借鉴 `-harvest` 的 TTL）——上游会恢复、能力会变，
  **一次误判不得永久除名**
- 电池的**判分是纯代码**（`grader.Judge` 为确定性字符串匹配，零网络调用），
  故能力准入**不消耗判官额度、不依赖付费 token**；付费模型可作为**校准基准**
  （开跑前确认题目本身可答），但基准缺席时结论应为 `未测`，**不得默认通过或失败**
  —— 与上一条严格策略配合：基准缺席 ⇒ 该轮**整体不产出准入结论**，而不是全判不过

### 五、测量独立性：网关只**消费**能力结论，不**自证**

- 能力测量必须由**独立路径直打上游**产出（不经网关转发），避免"用网关测网关"
- 评估器**不内置、按需调用**：它是**决策输入**（产一张准入选表），
  不是运行时常驻依赖 ⇒ 网关不因评估器缺席而不可用
- 收掉的是"常驻进程"，保留的是"**独立测量**"这条性质

### 状态机（扩展 ADR-003 的免费/付费分层）

```
                   ┌── 快层：额度耗尽 / 不可达 ──┐
                   │   （按 PlatformKind 定粒度） │
   正常池 ─────────┤                              ├──────→ 冷却池
                   └── 慢层：能力实测未通过 ──────┘           │
                                                              │
   正常池 ←──────── 恢复判据（快层恢复 + 慢层重测通过）────────┘
```

## 理由

- **分层是必要的**：三件事的时间尺度差几个数量级（秒 / 秒 / 小时），用一套窗去判必然误伤其一
- **粒度必须跟平台性质走**：单体厂商与聚合商的故障相关性相反，同一粒度必在一侧产生假死
- **可逆是准入的前提**：上游供给与模型能力都会变，不可逆的除名等于把偶发故障永久固化
- **独立性是本项目既有教训**：2026-09-30 的 44/44 误判，正是"判据与被测对象耦合"的现场复现

## 影响

- **正面**：模型级故障不再拖累整池判定；能力结论与网络故障分离；供给塌缩（如 xkiro 闲置）会**立即可见**
- **负面**：新增模型级状态与周期任务，复杂度上升；`platform_kind` 若写错会导致粒度用反（故需评审把关）
- **对外**：`/health` 与 `/doctor` 需增加"每模型健康/冷却/能力"维度，供上层消费

## 已定（2026-10-01 评审决议）

| # | 待定项 | 决议 |
|---|---|---|
| 1 | `platform_kind` 手写还是自动推断 | **自动推断**（按 ID 有无 `owner/` 前缀，provider 内多数形态为准，混合则告警） |
| 2 | 快层探测的实现位置 | **复用 `-harvest` 的探测循环**，不另起一套 |
| 3 | 能力题组的驱动方式 | **首次准入 + 按需重测**（不做周期常跑；由快层信号触发重测） |
| 4 | `未测` 模型的策略 | **不入池（严格）**——"没测过"与"没通过"同效；接受首次准入前的空窗 |
| 5 | 与"字面模型路由短路"缺陷的先后 | **路由缺陷为前置，先修**（不修则准入结论再准，模型也够不着） |

## 替代方案

| 方案 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| 维持现状（仅 key 级池 + 人工 kinds） | 零改动 | 供给塌缩不可见；能力标签无依据；本次误判会复发 | 放弃 |
| 只做模型级池，不分平台性质 | 改动较少 | 单体厂商侧必然产生"平台恢复后 key 仍冷却"的假死 | 放弃 |
| 把能力评估内置进网关常驻 | 部署单元少 | **判据自噬**：网关降级时把自己的失败记到模型头上 | 放弃 |
| 本 ADR（分层 + 双粒度 + 准入 + 独立测量） | 判据与粒度各归其位；误判可查可逆 | 复杂度上升，需评审把关字段语义 | **采纳** |
